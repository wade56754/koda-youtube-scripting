# Step 04 · 写稿

## 前置装载

- 创作者的品牌 voice 文件（定位 / 表达风格 / 禁用词表——按你自己的知识库配置）
- 创作者真本语料 grep：写前必须读本人写过的东西找语感。禁词检查通过 ≠ 语气像本人
- step02 材料包里标注「可直接进稿」的本人原话——**优先原样或微调使用**，这是全片人味的来源
- **同题材范本通读（硬流程）**：按 `reference/genre-emotion-map.md` 定的题材，从自备叙事语料库选 1 篇同题材原稿**完整通读**当活范本。范本与任何模板表格冲突时，以范本为准

## 写作规则

1. 按 structure.md 时间轴填字，不改结构；结构有问题回 step03
2. **语速口径**：实测自己的口播语速（参考值 280 字/分钟，因人而异）。每块的时间戳和字数必须对得上，写完逐块核对；对不上就改字数或改时间戳，禁止挂名不符实的时间标
3. **产出格式 = 结构标注版草稿**：交付的不是干净逐字稿，是带结构标注的初稿——每块标「块名 + 时间段 + 字数 + 作用」，块内每段标结构件角色（钩子 / 承诺 / 先手拆质疑 / Setup / Tension / Payoff / 段尾钩 / 边界声明 / 开放问题）。干净版提词稿在创作者终审定稿后另出
4. **视角规则**（叙事型）：场景里用"过去的我"（不知道结局），解释时用"现在的我"。禁止把后来才有的认识装进当时的脑子
5. **主谓字面成立**：主语必须真的能完成后面的动作。界面只能显示/要求/跳转，抽象名词不能干人的动作（风险不能"长"，经历不能"留话"）。技术与事实解释段默认零装饰比喻
6. **真实性**：所有案例来自真实素材；所有具体数字有可考来源，否则模糊化或显式标注为修辞
7. 每个 STP 块写完自查：这块的 Tension 是真悬念还是拖延？段尾钩在不在？
8. 画面证据清单同步产出：每个数据点标注对应的后台截图或画面素材
